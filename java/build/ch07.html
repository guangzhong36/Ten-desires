从 C 到 Java:文件世界的翻译

C 里的一切都是 FILE*:fopen/fread/fwrite/fclose。Java 里没有 FILE*,取而代之的是"流(stream)"体系:字节流(InputStream/OutputStream)按字节搬数据,字符流(Reader/Writer)按字符搬数据。而字符流底层还是字节流——中间垫着一层"编码转换器"。C 的 printf/fprintf 到 Java 是 PrintStream/PrintWriter。

最大的坑是编码。C 程序员在 Linux 上写文件,char 数组默认 UTF-8,基本没乱码问题;Java 里"读文件用什么字符集"是显式决策——new FileReader(file) 用平台默认字符集(Windows 上可能是 GBK!),读 UTF-8 文件直接乱码。铁律:读写文本一律显式指定 UTF-8。乱码问题 90% 由此而来。

NIO.2 是"现代姿势"。老 API(File、FileInputStream)啰嗦且容易漏关;JDK7 的 Path/Files 把"读整个文件、拷贝、移动、遍历"变成一行调用,配合 try-with-resources 几乎没有资源泄漏机会。生产代码应当以 NIO.2 为主,老 API 能读懂即可。

序列化是 C 没有的直接对应物。C 存结构体用 fwrite 裸写内存(字节序、版本问题一堆);Java 的 Serializable 把对象图整体变成字节流,再原样恢复。它不跨语言、有安全风险,但"Java 到 Java 的持久化/传输"非常方便——生产里常用于缓存与 RPC 传输(现代框架更推荐 JSON/Protobuf,本章 §7.7 讲选择)。

§7.1 流的世界观

7.1.1 四大基类与包装模式

方向字节流(处理 byte)字符流(处理 char/字符串)C 对应
读InputStream(FileInputStream 等)Reader(FileReader 等)fread / fgets
写OutputStream(FileOutputStream 等)Writer(FileWriter 等)fwrite / fprintf

包装模式是 Java 流的灵魂:基础流只管"连接数据源/目的地",装饰流负责"加缓冲、转字符、按行读"。一个完整流 = 基础流 + 若干装饰流,最外层装饰流决定"用起来多方便"。读文本文件的经典组合:

FileInputStream -> InputStreamReader -> BufferedReader

对应到 C:FILE* 内部其实也是"系统 fd + 用户态缓冲"的两层结构,只是 C 帮你包好了;Java 把每一层都拆开让你选。

重点:流的五个常识
  • 流是单向的:读流不能写,写流不能读;要读写一个文件就开两个流
  • 流必须关闭:try-with-resources 包住最外层流,内层自动关
  • 读到最后返回 -1(字节流)或 null(readLine),不是异常
  • 写满缓冲要 flush():缓冲流把数据攒着,不 flush 可能丢尾巴
  • 流是顺序访问:没有 fseek 的自由定位不是日常需求,需要时用 RandomAccessFile(少见)

§7.2 字节流实战:文件复制

示例 7-1 字节流文件复制(经典三段式)
import java.io.FileInputStream;
import java.io.FileOutputStream;
import java.io.BufferedInputStream;
import java.io.BufferedOutputStream;
import java.io.IOException;

public class CopyBytes {
    public static void main(String[] args) throws IOException {
        // C 的 fopen("rb"/"wb") 对应:FileInputStream/FileOutputStream
        // 缓冲流:一次读 8KB 到内存,而不是逐字节系统调用
        try (var in = new BufferedInputStream(new FileInputStream("a.bin"));
             var out = new BufferedOutputStream(new FileOutputStream("b.bin"))) {
            byte[] buf = new byte[8192];
            int n;
            while ((n = in.read(buf)) != -1) {   // 读一坨;返回实际字节数
                out.write(buf, 0, n);            // 只写实际读到的部分
            }
        }   // 两个流自动关闭(先关 out 后关 in)
        System.out.println("复制完成");
    }
}
易错点 1:write 一定要用 "buf, 0, n"

最后一次 read 可能只填满一部分缓冲区,用 out.write(buf, 0, n) 只写有效部分;写 out.write(buf) 会把上一次残留的脏字节也写进去,文件末尾出现垃圾数据。这是文件复制代码最高频的 bug。同理,read 的返回值 n 每次都要检查。

§7.3 字符流与编码

7.3.1 为什么乱码:字节与字符之间隔着一层"翻译官"

磁盘上只有字节。"中" 在 UTF-8 里是 3 个字节 E4 B8 AD,在 GBK 里是 2 个字节 D6 D0。字符流就是"翻译官":读时按指定字符集把字节翻译成字符,写时反向翻译。翻译官选错(字符集不匹配) = 乱码。两个铁律:

  1. 读文本文件:FileReader 必须显式传 UTF-8,否则用平台默认(Windows 常见 GBK/UTF-8 混乱)
  2. 写文本文件:同一条铁律;写完 flush 或关闭
示例 7-2 字符流:显式 UTF-8 读 + 写
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

public class TextIo {
    public static void main(String[] args) throws IOException {
        Path path = Path.of("notes.txt");

        // 写法 1(老风格):手动组装装饰流
        try (var in = new BufferedReader(
                new java.io.InputStreamReader(
                        new java.io.FileInputStream(path.toFile()),
                        StandardCharsets.UTF_8))) {
            String line;
            while ((line = in.readLine()) != null) {   // 读一行;结尾返回 null
                System.out.println("读到: " + line);
            }
        }

        // 写法 2(现代):Files.newBufferedReader 一行拿到 UTF-8 BufferedReader
        try (var in = Files.newBufferedReader(path, StandardCharsets.UTF_8)) {
            String line;
            while ((line = in.readLine()) != null) {
                System.out.println("再读: " + line);
            }
        }

        // 写:newBufferedWriter 同样带字符集参数
        try (var out = Files.newBufferedWriter(path, StandardCharsets.UTF_8)) {
            out.write("第一行\n");
            out.write("第二行\n");       // 关流时自动 flush
        }
    }
}
易错点 2:FileReader/FileWriter 的默认字符集陷阱

new FileReader(file) 与 new FileWriter(file) 用平台默认字符集——在 Windows 上通常是 GBK,在 Linux 服务器上通常是 UTF-8。同一份代码两个平台行为不同,文件跨机器拷贝就乱码。生产规则:这两类直接禁用裸构造,要么用 new InputStreamReader(in, StandardCharsets.UTF_8),要么用 Files.newBufferedReader(path, UTF_8)。字符集问题必须在编译时就写死,不能依赖环境。

§7.4 NIO.2:Path 与 Files

7.4.1 现代文件 API 全家桶

Path 描述位置(对应 C 的路径字符串,但类型安全),Files 是静态工具类(对应 C 的 stat/rename/unlink 等系统调用)。日常 90% 的文件操作 Files 都有现成方法:

操作Files 方法C 对应
读整个文件Files.readString(path, UTF_8) / readAllLinesread + 循环
写整个文件Files.writeString(path, text, UTF_8)fwrite
拷贝Files.copy(src, dst, REPLACE_EXISTING)手工循环复制
移动/改名Files.move(src, dst)rename()
删除Files.deleteIfExists(path)unlink()
属性Files.size / exists / isDirectorystat()
遍历目录Files.list / Files.walk(递归)readdir 循环
创建目录Files.createDirectories(可多级)mkdir -p 的手工版
示例 7-3 Files 全家桶实战
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardCopyOption;

public class FilesDemo {
    public static void main(String[] args) throws IOException {
        // 多级目录一次建好(等价 mkdir -p)
        Path dir = Path.of("data", "2026", "08");
        Files.createDirectories(dir);

        // 写整个文件:UTF-8 显式指定;文本默认不换行,自己加 \n
        Path f = dir.resolve("report.txt");          // resolve = 拼路径
        Files.writeString(f, "2026-08-26 实验报告\n第7章\n", StandardCharsets.UTF_8);

        // 读整个文件(小文件专用)
        String content = Files.readString(f, StandardCharsets.UTF_8);
        System.out.println("内容:\n" + content);

        // 追加写:Append 参数
        Files.writeString(f, "追加一行\n", StandardCharsets.UTF_8,
                java.nio.file.StandardOpenOption.APPEND);

        // 拷贝 + 覆盖
        Path bak = dir.resolve("report.bak.txt");
        Files.copy(f, bak, StandardCopyOption.REPLACE_EXISTING);

        // 遍历目录(非递归)
        try (var stream = Files.list(dir)) {
            stream.forEach(p -> System.out.println("条目: " + p.getFileName()));
        }

        // 递归遍历
        try (var walk = Files.walk(Path.of("data"))) {
            walk.filter(p -> p.toString().endsWith(".txt"))
                    .forEach(p -> System.out.println("txt 文件: " + p));
        }

        // 清理:删除备份
        Files.deleteIfExists(bak);
        System.out.println("done");
    }
}
工程建议:Files 的边界

readString/readAllLines 只适合小文件(几 MB 以内);大文件必须流式处理(§7.2 的缓冲流或 Files.lines)。Files.list 返回的是流,必须 try-with-resources 关闭,否则句柄泄漏。另外 Path.of 与 Paths.get 等价,新代码用 Path.of。

§7.5 序列化与反序列化

7.5.1 对象 → 字节流 → 对象

类实现 java.io.Serializable(空接口,标记用),对象就能交给 ObjectOutputStream 写成字节,再用 ObjectInputStream 原样读回。serialVersionUID 是版本号:类结构变了(增删字段),UID 变了,老数据反序列化会抛 InvalidClassException。生产铁律:每个 Serializable 类都显式声明 serialVersionUID,不依赖编译器生成。

示例 7-4 序列化与版本控制
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.IOException;
import java.io.Serializable;
import java.nio.file.Files;
import java.nio.file.Path;

public class SerializeDemo {
    // 实现 Serializable 标记接口:不写任何方法
    static class Student implements Serializable {
        private static final long serialVersionUID = 1L;   // 显式版本号:铁律!

        final String name;
        final int score;

        Student(String name, int score) {
            this.name = name;
            this.score = score;
        }

        @Override
        public String toString() { return name + ":" + score; }
    }

    public static void main(String[] args) throws Exception {
        Path f = Path.of("student.dat");

        // 写:对象 → 字节流
        try (var out = new ObjectOutputStream(
                Files.newOutputStream(f))) {
            out.writeObject(new Student("张三", 88));
            out.writeObject(new Student("李四", 76));
        }

        // 读:字节流 → 对象(顺序必须与写一致)
        try (var in = new ObjectInputStream(
                Files.newInputStream(f))) {
            Student s1 = (Student) in.readObject();   // 需要强转
            Student s2 = (Student) in.readObject();
            System.out.println(s1 + " / " + s2);      // 张三:88 / 李四:76
        }
    }
}
易错点 3:反序列化的两大风险

① 安全风险:反序列化等于执行"数据里的指令",从不信任的来源(网络、用户上传)反序列化会被攻击者利用(经典 RCE 链)。生产原则:反序列化只用于"自己写、自己读"的数据;跨系统传输用 JSON(Jackson/Gson)。② 兼容性:字段增删会让旧数据读不出来——serialVersionUID 不变时,新增字段读回默认值(null/0),删除字段的数据会丢;对格式敏感的场景考虑版本字段或 JSON。

§7.6 Properties 配置文件

7.6.1 键值对配置的标准读法

Properties 读写 key=value 格式的 .properties 文件,是 Java 最传统的配置方式(现代项目也用 YAML,但 Properties 依然到处可见)。加载后用 getProperty 取配置,带默认值防 NPE。

示例 7-5 Properties 读写
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Properties;

public class ConfigDemo {
    public static void main(String[] args) throws IOException {
        Path cfg = Path.of("app.properties");

        // 写配置(演示;生产配置一般由运维/安装器生成)
        Properties p = new Properties();
        p.setProperty("server.port", "8080");
        p.setProperty("app.name", "教务系统");
        try (var out = Files.newBufferedWriter(cfg, StandardCharsets.UTF_8)) {
            p.store(out, "生成于演示");      // 注释头 + 键值对
        }

        // 读配置:标准生产姿势
        Properties loaded = new Properties();
        try (var in = Files.newBufferedReader(cfg, StandardCharsets.UTF_8)) {
            loaded.load(in);
        }
        int port = Integer.parseInt(
                loaded.getProperty("server.port", "8080"));   // 带默认值
        String name = loaded.getProperty("app.name", "未知");
        System.out.println("端口=" + port + ", 应用=" + name);
        // 取不到的键返回 null;getProperty(key, def) 给默认值
    }
}
工程建议:配置的读取时机

配置在启动时读一次,放进常量/不可变对象,不要在每次请求时重新读文件(慢且浪费)。生产配置常配合环境变量覆盖:代码读系统属性/环境变量优先,Properties 兜底:System.getenv("PORT") 存在就用它。配置中心(Nacos/Spring Cloud Config)本质还是"远程拉一份配置到本地再走这套逻辑"。

自测题

1. 读一个 UTF-8 文件出现乱码,可能的原因有哪些?排查顺序?

参考答案

原因:① 读取字符集不是 UTF-8(如 FileReader 用了平台默认 GBK);② 文件本身不是 UTF-8(GBK/ANSI 编码);③ 多次转换叠加损坏。排查:先用工具确认文件字节(如 hexdump 看"中"是 E4B8AD 还是 D6D0),再确认代码里字符集参数,最后统一为显式 UTF-8 读写。乱码一旦写回文件就是不可逆损坏,务必先备份。

2. 下面代码有什么问题?byte[] buf = new byte[4096]; in.read(buf); out.write(buf);

参考答案

read 的返回值没检查,且 write 写整个 buf。最后一次 read 可能不足 4096 字节,write(buf) 会把上次残留内容一起写进去,文件尾部出现垃圾。正确写法:int n; while ((n = in.read(buf)) != -1) out.write(buf, 0, n);

3. 序列化版本兼容:类加了 serialVersionUID = 1L 后新增一个字段,读旧数据会怎样?为什么显式声明 UID?

参考答案

UID 不变时,新增字段读回默认值(引用 null、数字 0),不抛异常——这是"宽松兼容";删除字段的数据会丢失。若没显式声明 UID,编译器根据类结构自动生成,增删字段后 UID 变化,读旧数据抛 InvalidClassException。所以显式声明让版本行为可预期,并且改版时你能主动决定是否 bump 版本。

4. 从不可信来源(用户上传文件)反序列化,为什么危险?

参考答案

反序列化会实例化数据中指定的类并调用其方法,攻击者可以构造恶意字节流触发危险类(如 Runtime、JNDI 相关)执行任意代码——著名的反序列化 RCE。生产铁律:只对可信数据反序列化;跨系统用 JSON 并校验字段白名单。

5. 需要把 2GB 的日志文件按行统计行数,用 readString 还是流式?写出代码。

参考答案
long count = 0;
try (var lines = Files.lines(Path.of("big.log"), StandardCharsets.UTF_8)) {
    count = lines.count();
}
System.out.println("行数: " + count);

必须流式:readString 会把 2GB 塞进内存直接 OOM。Files.lines 返回惰性流,一行一行读,内存占用与文件大小无关。同理大文件处理用 stream() 的过滤/映射,别先读全量。

6. 追加日志时用 writeString 加 APPEND,多个线程同时写会怎样?正确做法?

参考答案

并发写同一文件会互相覆盖/交错,出现损坏或丢行。生产用日志框架(logback/log4j2)管理文件追加、滚动与并发;实在要手写,用单线程写队列或加锁,但那是重复造轮子。多线程与锁在本书第9章展开。

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardCopyOption;
import java.nio.file.StandardOpenOption;
import java.util.ArrayList;
import java.util.List;
import java.util.Properties;

/** 成绩单文件处理器 —— 第7章综合实验参考答案
 *  覆盖:Properties、NIO.2 读写、流式复制、序列化、拷贝与遍历
 */
public class ScoreFileProcessor {

    // 任务 5:序列化数据类,显式版本号
    static class Student implements Serializable {
        private static final long serialVersionUID = 1L;

        final String name;
        final int score;

        Student(String name, int score) {
            this.name = name;
            this.score = score;
        }

        @Override
        public String toString() { return name + ":" + score; }
    }

    public static void main(String[] args) throws Exception {
        // 任务 1:读取配置(带默认值)
        Properties cfg = new Properties();
        if (Files.exists(Path.of("config.properties"))) {
            try (var in = Files.newBufferedReader(Path.of("config.properties"),
                    StandardCharsets.UTF_8)) {
                cfg.load(in);
            }
        }
        String title = cfg.getProperty("report.title", "期末成绩报告");
        String outDir = cfg.getProperty("output.dir", "out");
        Path out = Path.of(outDir);
        Files.createDirectories(out);                  // 目录不存在就建
        System.out.println("== 任务 1 配置: " + title + " / " + outDir);

        // 任务 2:Files 读 CSV 并解析
        List<Student> students = new ArrayList<>();
        try (var reader = Files.newBufferedReader(Path.of("scores.csv"),
                StandardCharsets.UTF_8)) {
            String line;
            while ((line = reader.readLine()) != null) {
                line = line.trim();
                if (line.isEmpty() || line.startsWith("#")) {
                    continue;                          // 跳过空行与注释
                }
                String[] parts = line.split(",");
                if (parts.length != 2) {
                    System.out.println("跳过格式错误行: " + line);
                    continue;
                }
                students.add(new Student(parts[0].trim(),
                        Integer.parseInt(parts[1].trim())));
            }
        }
        System.out.println("== 任务 2 解析 " + students.size() + " 条成绩");

        // 任务 3:统计并写报告
        int sum = 0, pass = 0, max = 0;
        for (Student s : students) {
            sum += s.score;
            if (s.score >= 60) pass++;
            if (s.score > max) max = s.score;
        }
        double avg = students.isEmpty() ? 0 : (double) sum / students.size();
        StringBuilder report = new StringBuilder();
        report.append("==== ").append(title).append(" ====\n");
        report.append("人数: ").append(students.size()).append("\n");
        report.append(String.format("平均分: %.1f%n", avg));
        report.append("最高分: ").append(max).append("\n");
        report.append("及格人数: ").append(pass).append("\n");
        Path reportFile = out.resolve("report.txt");
        Files.writeString(reportFile, report.toString(), StandardCharsets.UTF_8);
        System.out.println("== 任务 3 报告已生成: " + reportFile);

        // 任务 4:缓冲字符流逐行备份(流式,不整文件进内存)
        Path backup = out.resolve("backup.csv");
        try (var reader = Files.newBufferedReader(Path.of("scores.csv"),
                StandardCharsets.UTF_8);
             var writer = Files.newBufferedWriter(backup, StandardCharsets.UTF_8)) {
            String line;
            while ((line = reader.readLine()) != null) {
                writer.write(line);
                writer.newLine();
            }
        }
        System.out.println("== 任务 4 备份完成: " + backup);

        // 任务 5:序列化整个列表,再读回验证
        Path dat = out.resolve("students.dat");
        try (var oos = new ObjectOutputStream(Files.newOutputStream(dat))) {
            oos.writeObject(students);
        }
        try (var ois = new ObjectInputStream(Files.newInputStream(dat))) {
            @SuppressWarnings("unchecked")
            List<Student> restored = (List<Student>) ois.readObject();
            System.out.println("== 任务 5 反序列化验证: " + restored.size() + " 条,"
                    + "首条 " + restored.get(0));
        }

        // 任务 6:拷贝报告 + 遍历目录
        Path copy = out.resolve("report.backup.txt");
        Files.copy(reportFile, copy, StandardCopyOption.REPLACE_EXISTING);
        System.out.println("== 任务 6 输出目录内容:");
        try (var list = Files.list(out)) {
            list.sorted().forEach(p ->
                    System.out.println("   " + p.getFileName() + " (" + sizeOf(p) + " B)"));
        }

        System.out.println("== 任务 7 处理完成 ==");
    }

    static long sizeOf(Path p) {
        try {
            return Files.size(p);
        } catch (Exception e) {
            return -1;
        }
    }
}

设计说明:任务 4 特意用流式逐行复制(与任务 2 的整文件读形成对照):CSV 如果很大,readString 会 OOM,而这里内存占用恒定。任务 5 的 @SuppressWarnings("unchecked") 是强转泛型列表的标准姿势。扩展方向:用 Files.walk 递归处理子目录、把统计结果同时写 JSON 版本(第13章引入第三方库时会讲)、对超大文件用 Stream 并行统计(第10章)。
