§14.1 类型全景:编译器知道得比你多

C++ 里每一个表达式都有静态类型,编译器在编译期就"知道"它是什么:是 int 还是 const char*,是引用还是指针,是基类还是派生类。这个知识是类型系统给你的一切能力的来源:重载决议靠它、模板实例化靠它、运算符语义靠它、编译错误报告也靠它。C++ 的类型检查不是运行时行为——编译通过的类型正确代码,类型错误在运行前就被拦截了。理解类型系统的第一课:类型不是注释,是约束。

类型谱系要先理清几个维度。按性质分:对象类型(算术、指针、数组、类、枚举)、引用类型(左值引用、右值引用)、函数类型与 void。按限定分:const 限定与 volatile 限定。按复合方式分:数组、指针、引用、成员指针。多态类型是含虚函数的类,它们是 dynamic_cast 与 typeid 的适用对象。这条谱系决定了每个类型能参与什么操作:数组名会衰减成指针、函数名会衰减成函数指针、const 对象不能调用非 const 成员——全是类型系统在工作。

还有价值类别(value category)一维:表达式分为左值(有名字、可取地址、可持久)与右值(临时值、即将消亡)。C++11 的右值又细分为纯右值(x + 1 的临时结果)与将亡值(std::move(x) 的结果)。价值类别决定移动语义能不能生效:move 返回将亡值,所以能触发移动构造。写代码时不用背全套理论,记住一句:左值有身份,右值是临时的;std::move 不移动任何东西,它只是把表达式转成将亡值,让重载决议选到移动路径。

§14.2 隐式转换:编译器替你做的类型体操

隐式转换(标准转换)是编译器自动执行、不需要写任何语法的转换。最日常的一档是整型提升:short、char、bool 参与运算时提升为 int,这是"从小到更大且不丢值"的安全转换。第二档是整型转换:int 转 long、long 转 int,方向任意,可能丢值,但编译器默默允许——只在花括号初始化里被禁止(窄化检查)。第三档是浮点转换:float 转 double 安全,double 转 float 可能丢精度。第四档是算术转换:两个不同算术类型做运算时,编译器找"公共类型"(如 int 与 double 运算,结果类型是 double),规则表复杂且常有直觉意外。

清单 14-1 隐式转换的现场
#include <iostream>
#include <cstdint>

int main() {
    short s = 1000;
    int i = s;                     // 整型提升:short -> int,安全
    long long ll = i;              // 整型转换:安全方向

    unsigned u = 4000000000u;      // 4 十亿
    int n = static_cast<int>(u);   // 有符号/无符号混用前先想清楚
    std::cout << "u=" << u << ", n=" << n << "\n";  // n 溢出为负

    double d = 3.14159;
    int truncated = d;             // double -> int 截断,丢弃小数
    std::cout << "truncated=" << truncated << "\n";

    int big = 2000000000;
    // 窄化警告(花括号初始化禁止):
    // char c = {big};              // 错误:窄化转换
    char c = static_cast<char>(big);
    std::cout << "char 包装: " << (int)c << "\n";

    // 经典陷阱:无符号与有符号比较
    int neg = -1;
    unsigned pos = 1;
    if (neg < pos) {               // 负转成巨大无符号数,比较结果反直觉
        std::cout << "neg < pos 为真\n";
    } else {
        std::cout << "neg < pos 为假(陷阱触发!)\n";
    }
    return 0;
}

隐式转换的第二大类是类类型转换:单参数构造函数充当"从别的类型构造本类型"的转换通道,转换运算符(operator double() 之类)充当"本类型转成别的类型"的通道。两者叠加,语言允许一串隐式转换自动发生——这正是陷阱所在:意外转换、歧义重载、难以追踪的类型体操。C++11 的 explicit 关键字就是给这些转换通道上锁:explicit 构造函数与 explicit 转换运算符只允许显式转换(static_cast、直接初始化),禁止隐式发生。

工程纪律:数值边界转换要么显式写出 static_cast,要么开 -Wconversion 让隐式窄化报警;有符号与无符号的混用比较几乎全是 bug 温床,比较前统一转型;类类型转换一律 explicit,需要隐式行为时深思熟虑再放开。隐式转换是便利,更是地雷,默认关掉它。

C 的写法C++ 的写法说明
隐式转换一律静默发生花括号初始化 + -Wconversion 拦截窄化C++ 给"丢值"的转换加了编译期刹车
enum 常量隐式转 int,泄漏进全局enum class 不隐式转换,作用域封闭C++11 起枚举是真正的强类型
单参构造函数与转换无开关explicit 锁住隐式类转换隐式转换通道默认关闭,意图明确
易错点 1:无符号下标的递减陷阱

for (std::size_t i = v.size() - 1; i >= 0; --i) 是教科书级陷阱:i 减到 0 后再减一次,绕回 size_t 的最大值,条件 i >= 0 永远为真,循环永不停;v 为空时 v.size() - 1 直接就是最大值,更是隐蔽。修法:用反向迭代器(rbegin/rend)、用后置递减惯用法 for (size_t i = n; i-- > 0;),或显式转成有符号再递减。

§14.3 四种显式转换:各司其职的 cast

显式转换(强制转换)是程序员主动要求的类型变换。C++ 提供四种风格化 cast,取代了 C 的万能转型 (类型)表达式。static_cast 是"合理的显式转换":数值类型互转、基类指针/引用与派生类指针/引用互转(向下转换不做运行时检查,是契约型)、void* 与具体指针互转。它是默认选择,能做 90% 的活。reinterpret_cast 是"位级重解释":把一种指针的位模式直接当另一种指针用,不做任何检查与调整,是最后手段——真实用途只有底层编解码、与 C 库对接等极少数场景。

清单 14-2 四种 cast 的分工
#include <iostream>
#include <cstring>
#include <cstdint>

int main() {
    // static_cast:数值与类型的合理转换
    double d = 3.75;
    int n = static_cast<int>(d);        // 截断 3
    std::cout << n << "\n";

    // reinterpret_cast:位重解释(危险,极少用)
    std::uint64_t bits = 0x3ff0000000000000ull;   // 1.0 的 IEEE 754 位模式
    double x = *reinterpret_cast<double*>(&bits);
    std::cout << "位模式解释为 double: " << x << "\n";
    // 安全做法(别名规则友好):
    double y;
    std::memcpy(&y, &bits, sizeof(bits));
    std::cout << "memcpy 解释: " << y << "\n";

    // const_cast:去掉 const(只用于修正"误标 const"的接口)
    const int ci = 42;
    int* p = const_cast<int*>(&ci);
    // *p = 7;                        // 危险:写真 const 对象是未定义行为

    // 类型别名双关用 memcpy,别用 reinterpret_cast(严格别名规则)
    float f = 1.5f;
    std::uint32_t fb;
    std::memcpy(&fb, &f, sizeof(f));
    std::cout << "float 位模式: 0x" << std::hex << fb << std::dec << "\n";
    return 0;
}

const_cast 是四个 cast 里最需要警惕的:它去掉对象的 const 限定。如果被去 const 的对象本身是"真 const"(声明为 const 的变量),写入它是未定义行为;如果它只是"经 const 接口传递"的普通对象,去掉 const 写入则是合法的。它的正当用途只有两种:调用一个错误标成非 const 的旧库函数,以及 const 成员函数内共享可变状态的底层细节(这种情况现代代码应该用 mutable 成员)。日常业务代码里出现 const_cast,先假定是设计问题。

dynamic_cast 是唯一做运行时检查的 cast:沿虚继承链把基类指针/引用转回派生类,转不动返回 nullptr(指针版本)或抛 std::bad_cast(引用版本)。它依赖 RTTI,只能用于多态类型。工厂函数返回基类指针、调用方需要特定派生接口时,它是正解;但如果代码里 dynamic_cast 满屏都是,说明设计在退化——应该靠虚函数与访问者模式消化分支。C 语言完全没有对应物,这正是 C++ 运行时多态语言特性的延伸。

清单 14-3 dynamic_cast 的运行时检查
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Shape {                         // 多态基类:有虚函数
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    double r;
    explicit Circle(double radius) : r(radius) {}
    double area() const override { return 3.14159 * r * r; }
};

class Rect : public Shape {
public:
    double w, h;
    Rect(double width, double height) : w(width), h(height) {}
    double area() const override { return w * h; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(1.0));
    shapes.push_back(std::make_unique<Rect>(2.0, 3.0));

    for (const auto& s : shapes) {
        // 运行时检查:真是 Circle 才转成功
        if (const auto* c = dynamic_cast<const Circle*>(s.get())) {
            std::cout << "圆, 半径 " << c->r
                      << ", 面积 " << s->area() << "\n";
        } else {
            std::cout << "其他图形, 面积 " << s->area() << "\n";
        }
    }
    return 0;
}
C 的写法C++ 的写法说明
(int)x 万能转型,无检查static_cast<int>(x) 语义明确C++ 四种 cast 各管一摊,转型意图可见
无运行时类型检查dynamic_cast 运行时验证多态向下转换 C 做不到,只能手工字段判定
类型双关靠指针强转reinterpret_cast + memcpyC 的强转常违反严格别名规则,是 UB 源
易错点 2:reinterpret_cast 的类型双关是未定义行为

把 float 的位模式 reinterpret_cast 成 int 读,"看着能跑",实则是严格别名规则的违反:优化开启后编译器按"类型不同就不会互相影响"重排代码,结果未定义。安全做法是 std::memcpy 或 C++20 的 std::bit_cast。同理,把较小对象强转成较大指针再解引用是对齐错误,ARM 上直接崩溃。reinterpret_cast 前后都要想清楚"位布局依据"是什么。

§14.4 auto 与 decltype:让编译器写类型

auto 让编译器从初始化表达式推导变量类型。规则第一条:auto 推导值类型,const 与引用被剥掉(auto x = 常量引用对象,x 是副本);想要它们,写 const auto、auto&、const auto&、auto&&。第二条:auto&& 对左值实参推导为左值引用,对右值实参推导为右值引用——这是万能引用的基础(第10章提过)。第三条:auto 的推导发生在编译期,和模板推导同一套规则,因此 auto 变量必须有初始化器,初始化器决定一切。auto 的好处不是"少打字",而是"类型永不漂移":改接口返回类型,用 auto 的地方自动跟随。

decltype 是另一个方向:直接取出表达式或实体的声明类型。规则要记两条:decltype(实体名) 得到实体本身的声明类型(带引用与 const);decltype(表达式) 得到表达式结果类型,而表达式是左值时额外加引用(decltype((x)) 与 decltype(x) 不同——括号让 x 变成表达式)。decltype(auto) 让函数返回类型的推导完全按 decltype 规则进行,把"完美转发"写进返回类型(第10章的转发函数常以此结尾)。C++14 起函数返回类型可以裸写 auto 让编译器推导,但对外接口建议显式写出返回类型:接口要自文档化,推导适合内部辅助函数。

清单 14-4 auto 与 decltype 推导规则
#include <iostream>
#include <vector>
#include <string>

template <typename T>
decltype(auto) first(std::vector<T>& v) {
    return v.front();                // 返回 T&,不是副本
}

int main() {
    std::vector<std::string> names{"张三", "李四"};

    auto a = names[0];               // a 是 std::string 副本
    auto& ar = names[0];             // ar 是引用,改动影响容器
    const auto& cr = names[0];       // 常引用,只读不拷贝
    ar = "王五";
    std::cout << names[0] << "\n";   // 王五

    decltype(names[0]) d = names[1]; // d 与 names[0] 同型:引用
    d = "赵六";                       // 改的是 names[1]
    std::cout << names[1] << "\n";

    auto& f = first(names);          // decltype(auto) 返回引用
    f = "孙七";
    std::cout << names[0] << "\n";

    // decltype((x)) 是表达式,带引用;decltype(x) 是实体名,原样
    int x = 5;
    static_assert(std::is_same_v<decltype(x), int>);
    static_assert(std::is_same_v<decltype((x)), int&>);
    return 0;
}

结构化绑定(C++17)是 decltype 思路的日常应用:auto [k, v] = map 把 pair/元组/数组的结构拆开绑定,让"取类型"的样板消失。注意绑定的生命周期与副本语义:auto [k, v] 默认复制,auto& [k, v] 才是引用。有了 auto、decltype、结构化绑定,显式写类型只在需要控制存储与接口时出现——这正是现代 C++ 的"类型由编译器保证,人只写意图"的写法。

易错点 3:auto 剥引用,改动"失效"

auto x = 某引用; 拿到的是副本,之后对 x 的修改不反映到原对象——比显式写类型时更隐蔽,读代码的人看不出这是副本。数组更是重灾区:auto a = arr; 直接把数组退化成指针,失去数组语义与 sizeof 信息。修法:想写原对象就用 auto& 或 const auto&,想保留数组语义用 auto& a = arr 绑定引用。

§14.5 类型萃取:把类型当数据用

type_traits 头文件提供了一整套编译期类型查询与变换工具,它们全部在编译期求值,零运行时成本。查询类:is_same、is_integral、is_floating_point、is_class、is_pointer、is_reference、is_const、is_convertible、is_base_of。变换类:remove_reference、remove_const、decay(剥掉引用与 const、数组转指针、函数转函数指针)、conditional(编译期三元)、common_type(找公共类型)。C++17 起每个 trait 都有 _v 后缀变量模板(is_same_v<T,U>),写法更短;旧代码用 ::value 加 typename 也常见。

清单 14-5 类型萃取实用组合
#include <iostream>
#include <string>
#include <type_traits>
#include <vector>

// 编译期断言:类型关系是"硬契约"
static_assert(std::is_integral_v<int>, "int 必须是整型");
static_assert(!std::is_integral_v<double>, "double 不是整型");
static_assert(std::is_base_of_v<std::string, std::string>);

// decay:剥掉引用/const,数组转指针
template <typename T>
void showType() {
    using U = std::decay_t<T>;
    if (std::is_integral_v<U>)      std::cout << "整型\n";
    else if (std::is_floating_point_v<U>) std::cout << "浮点\n";
    else if (std::is_pointer_v<U>)  std::cout << "指针\n";
    else                            std::cout << "其他\n";
}

// conditional:编译期二选一
template <typename T>
using Storage = std::conditional_t<
    (sizeof(T) <= 8),               // 小对象用值,大对象用指针
    T,
    const T*>;

int main() {
    int arr[10];
    showType<decltype(arr)>();      // 数组 -> decay 成 int* -> 指针
    showType<const int&>();         // 引用/const 剥掉 -> 整型
    showType<double>();             // 浮点

    Storage<int> s1 = 3;            // 值存储
    std::string big = "大对象";
    Storage<std::string> s2 = &big; // 指针存储
    std::cout << s1 << " " << *s2 << "\n";
    return 0;
}

萃取与 if constexpr 的组合是 C++17 之后的"编译期派发"主流:if constexpr (std::is_integral_v<T>) { 整数版本 } else { 通用版本 },不满足的分支连编译都不参与,替代了第10章的 enable_if/SFINAE 大部分场景。constexpr if 让类型分支的代码可读性直线上升,是元编程从"技巧"走向"日常"的关键一步。C++20 的 concepts 更进一步,把"类型必须满足什么约束"写成具名的断言:template <std::integral T> 直接表达意图,编译错误信息也清晰得多。这三个工具(萃取、if constexpr、concepts)构成了现代 C++ 的类型驱动编程语言。

C 的写法C++ 的写法说明
sizeof 与 _Generic(C11) 有限判断is_integral、is_same 等全套萃取C++ 的编译期类型查询是图灵完备的
类型分支靠宏与运行时 ifif constexpr + type_traits不满足的分支不生成代码,零成本
数组/函数类型几乎不可操作decay、remove_reference 精确变换类型变换是可组合的编译期函数

§14.6 类型安全实践:让错误在编译期显形

类型系统的终极价值是让"不可能的状态"无法表达。工程上把它落实到四点。第一,用 enum class 代替裸 enum:作用域限定的枚举不会泄漏常量名,不能隐式转成 int,比较与传递都受类型约束——C 的裸枚举和 #define 常量在 C++ 里没有位置。第二,用 std::variant 代替裸 union:variant 记住当前持有什么类型,用 std::visit 安全访问,而 union 是"谁写谁负责"的裸内存区,极易踩错字段。第三,转换纪律:数值边界转换显式化、窄化报警开启、类型双关用 memcpy、const_cast 只在修接口、reinterpret_cast 写注释说明位布局依据。

清单 14-6 enum class 与 variant 的类型安全
#include <iostream>
#include <string>
#include <variant>

// 作用域枚举:不泄漏名字,不隐式转 int
enum class Color { Red, Green, Blue };
enum class Priority { Low, High };   // 同名常量互不干扰

int toInt(Color c) {
    return static_cast<int>(c);      // 显式转换才拿到数值
}

// variant:类型安全的多选一
struct Circle { double r; };
struct Rect   { double w, h; };

using Shape = std::variant<Circle, Rect>;

double area(const Shape& s) {
    return std::visit([](const auto& sh) -> double {
        using T = std::decay_t<decltype(sh)>;
        if constexpr (std::is_same_v<T, Circle>) {
            return 3.14159 * sh.r * sh.r;
        } else {
            return sh.w * sh.h;
        }
    }, s);
}

int main() {
    Color c = Color::Red;
    std::cout << "红色序号: " << toInt(c) << "\n";

    Shape s1 = Circle{2.0};
    Shape s2 = Rect{3.0, 4.0};
    std::cout << area(s1) << " " << area(s2) << "\n";
    return 0;
}

第四,让类型关系成为契约:static_assert 写在模板入口,把"调用方必须满足的前置条件"变成编译期硬失败;公共 API 的返回类型写清楚(别用 auto 糊接口);需要运行时多态时用 dynamic_cast 并显式处理失败分支,而不是赌"一定是那个类型"。类型安全不是消灭所有转换——那是乌托邦——而是让每个转换都有名字、有位置、有检查,错误发生时,报错在编译期而不是线上。

清单 14-7 转换纪律检查清单
#include <iostream>
#include <cstddef>

// 纪律 1:边界转换显式化,禁止隐式窄化
long toBytes(std::size_t pages) {
    return static_cast<long>(pages) * 4096;   // 先扩大再乘,不丢位
}

// 纪律 2:索引遍历要想到无符号语义
void dump(const int* xs, std::size_t n) {
    for (std::size_t i = 0; i < n; ++i) {     // 正向无风险
        std::cout << xs[i] << " ";
    }
    for (std::size_t i = n; i-- > 0; ) {      // 反向:后置递减惯用法
        std::cout << xs[i] << " ";
    }
    std::cout << "\n";
}

int main() {
    int arr[] = {1, 2, 3};
    dump(arr, 3);
    std::cout << toBytes(4) << "\n";        // 16384
    return 0;
}

自测题

1. 隐式转换分哪几档?为什么有符号与无符号混用比较是陷阱?

答案

整型提升、整型转换、浮点转换、算术转换(找公共类型)。有符号转无符号按模运算重解释:-1 转 unsigned 成为巨大的正数,与正数比较时结果反直觉;混用比较前应显式统一类型。

2. 四种显式转换分别适用什么场景?C 的万能转型 (T)x 为什么在 C++ 里是坏味道?

答案

static_cast 用于合理的显式转换(数值、类层次);dynamic_cast 用于运行时检查的多态向下转换;const_cast 用于修正误标 const 的接口;reinterpret_cast 用于位级重解释。C 的转型是一把锤子,不区分意图,容易掩盖错误转换,且 reinterpret 与 const 相关错误在 C 里无法表达与拦截。

3. auto x = v[0] 与 auto& x = v[0] 有什么区别?decltype(x) 与 decltype((x)) 呢?

答案

前者复制一份,后者是引用(修改会影响容器)。decltype(x) 是实体名,得到声明的类型;decltype((x)) 把 x 当表达式求,左值表达式带引用,所以是 int&。

4. if constexpr (std::is_integral_v<T>) 相比第10章的 enable_if 优势在哪?

答案

可读性:分支代码线性排列,不再需要层层 enable_if 签名技巧;不满足的分支不参与编译、不生成代码;配合 _v 后缀的 trait 变量模板,意图直接。enable_if 仍在库实现与 SFINAE 场景有用,但日常派发用它足矣。

5. 写出三个"让类型错误在编译期显形"的具体做法。

答案

用 enum class 与 std::variant 替代裸 enum 与裸 union,让非法组合无法表达;模板入口写 static_assert 把前置条件变成编译失败;开启 -Wconversion 让隐式窄化报警;公共 API 返回类型显式写出并配合 nodiscard(第12章)。

实验:类型安全工具库

本实验把本章知识点组装成一个小的类型工具库:showType 用 type_traits 打印类型的类别,以 const char* 的参数统一字符串化(演示 const_cast 的正确用法);safeAdd 用 if constexpr 按整型/浮点派发并做溢出检查;Shape 用 variant 与 visit 计算面积(避免 dynamic_cast 的 ODR 顾虑);再演示 decltype(auto) 与 auto& 的引用语义。运行输出见注释。

实验:类型工具库 main.cpp
#include <iostream>
#include <string>
#include <variant>
#include <type_traits>
#include <limits>
#include <stdexcept>

// 覆盖:type_traits 查询
template <typename T>
const char* showType() {
    using U = std::decay_t<T>;       // 覆盖:decay 变换
    if constexpr (std::is_integral_v<U>)
        return "整型";
    else if constexpr (std::is_floating_point_v<U>)
        return "浮点";
    else if constexpr (std::is_pointer_v<U>)
        return "指针";
    else if constexpr (std::is_class_v<U>)
        return "类";
    else
        return "其他";
}

// 覆盖:if constexpr 编译期派发 + 溢出检查
template <typename T>
T safeAdd(T a, T b) {
    if constexpr (std::is_integral_v<T>) {
        if ((b > 0 && a > std::numeric_limits<T>::max() - b) ||
            (b < 0 && a < std::numeric_limits<T>::min() - b)) {
            throw std::overflow_error("整型溢出");
        }
        return a + b;
    } else {
        return a + b;                // 浮点分支,无溢出检查
    }
}

// 覆盖:std::variant 类型安全多选一
struct Circle { double r; };
struct Rect   { double w, h; };
using Shape = std::variant<Circle, Rect>;

double area(const Shape& s) {
    return std::visit([](const auto& sh) -> double {
        using T = std::decay_t<decltype(sh)>;
        if constexpr (std::is_same_v<T, Circle>)   // 覆盖:is_same
            return 3.14159 * sh.r * sh.r;
        else
            return sh.w * sh.h;
    }, s);
}

// 覆盖:decltype(auto) 返回引用
template <typename T>
decltype(auto) first(T& v) { return v.front(); }

// 覆盖:const_cast 修正"误标 const"的旧接口(只读,不改写)
const char* legacyFormat(const std::string& s) {
    // 旧库签名是非 const,这里 const_cast 只去掉接口层 const
    return const_cast<std::string*>(&s)->c_str();
}

int main() {
    // 覆盖:auto / auto& / const auto& 引用语义
    std::string name = "类型系统";
    auto copy = name;                // 副本
    auto& ref = name;                // 引用
    const auto& cre = name;          // 常引用
    ref += "进阶";
    std::cout << copy << " | " << cre << "\n";   // 类型系统 | 类型系统进阶

    // 覆盖:类型打印
    std::cout << showType<int>() << " " << showType<double&>()
              << " " << showType<const char*>() << "\n";

    // 覆盖:safeAdd 整型分支(会抛异常)与浮点分支
    try {
        std::cout << safeAdd(2147483640, 10) << "\n";   // 溢出异常
    } catch (const std::overflow_error& e) {
        std::cout << "捕获: " << e.what() << "\n";
    }
    std::cout << safeAdd(2.5, 3.25) << "\n";           // 5.75

    // 覆盖:variant + visit
    Shape s = Rect{3.0, 4.0};
    std::cout << "面积: " << area(s) << "\n";

    // 覆盖:decltype(auto) 引用返回
    std::string arr[] = {"甲", "乙"};
    auto& f = first(arr);
    f = "丙";
    std::cout << arr[0] << " " << arr[1] << "\n";

    // 覆盖:const_cast 修正旧接口
    std::cout << legacyFormat(name) << "\n";
    return 0;
}

工程实践 1:转换审计

给代码评审加一条固定项:任何 static_cast/reinterpret_cast/const_cast 都要回答"为什么这里需要显式转换"。说不出理由的转换就是设计缺口——通常是接口类型设计错了。reinterpret_cast 出现处必须带注释说明位布局依据与兼容保证。

工程实践 2:类型作为文档

把"合法的状态"编码进类型:用 enum class 与 std::variant 表达互斥状态,用 const 表达只读,用值类型表达所有权。类型注释不写"该传什么",而是让错的根本传不进来。配合 static_assert 把前置条件钉在编译期,线上事故在编译期就变成错误报告。

本章总结

类型系统是 C++ 最重要的安全网:隐式转换提供便利也埋雷,显式转换用四种 cast 各司其职,auto 与 decltype 让类型推导自动化,type_traits 把类型变成可编程的编译期数据,if constexpr 与 concepts 把类型分支变成可读的日常代码。最终纪律只有一条:让错误尽可能发生在编译期——类型用得越准,运行期越安静。至此 14 章走完,从变量到内存、从对象到泛型、从网络到类型系统,你已经掌握了现代 C++ 的完整地图。
